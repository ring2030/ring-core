# 限定本番向け差分仕様（PoCとの差分のみ）

対象: 1病院・少人数（目安 5〜20ユーザー）  
目的: PoCを「安全に運用開始できる状態」へ引き上げる

## 1. 仕様差分サマリ

PoCでは「動くこと」を優先した。限定本番では「安全に回せること」を優先する。  
差分は次の4系統に分ける。

- 認証・権限
- 監査・記録
- 運用・保守
- UI/エラー体験

## 2. 認証・権限（最優先）

### 2-1. デモ認証の廃止

- 現状: `ID=1 / PASS=1` が有効
- 変更:
  - 初回ログイン時のパスワード変更を必須化
  - パスワード最小要件（例: 10文字以上、英数混在）
  - ログイン失敗回数制限（例: 5回で15分ロック）

### 2-2. ロールの最低追加

- 現状: 実質 `nurse` 中心
- 変更:
  - `hospital_admin`: アカウント作成/無効化/所属変更可
  - `nurse`: ケア運用可、管理操作は不可
  - `viewer`: 閲覧のみ

### 2-3. API認可ルール固定

- すべての管理APIで `role` と `hospitalId` の両方を必須化
- 権限不足時は 403 を返し、監査ログに記録

## 3. 監査・記録

### 3-1. 監査ログ保存先

- 現状: JSONL簡易保存
- 変更:
  - FirestoreまたはサーバーDBへ永続化
  - 項目固定: `at`, `hospitalId`, `actorId`, `action`, `target`, `result`, `note`

### 3-2. 保持ポリシー

- 最低保持期間を定義（例: 180日）
- 月次でCSVエクスポートして保管できる手順を残す

## 4. 運用・保守

### 4-1. アカウント運用手順

- 入職: 発行→初回変更確認
- 異動: 所属変更と旧所属権限の剥奪
- 退職: 即日無効化

### 4-2. 定期棚卸し

- 月1回、`hospital_admin` が有効アカウント一覧を確認
- 不要アカウント・不要所属を削除

### 4-3. バックアップ/復旧

- 監査ログ・主要データのバックアップ周期を定義（例: 日次）
- 復旧手順を1ページ化（担当者、手順、連絡先）

## 5. UI/エラー体験

### 5-1. エラーメッセージ統一

- ログイン失敗、病院切替失敗、CSV失敗の文言を統一
- ユーザー向け文言と管理者向け文言を分ける

### 5-2. 再試行導線

- 失敗時に「再試行」「設定へ戻る」「問い合わせ先」を提示

## 6. 受け入れ基準（限定本番）

- `ID=1 / PASS=1` を無効化し、実運用アカウントのみでログイン可能
- 役割ごとの操作制限がAPIレベルで有効
- 監査ログが永続保存され、CSV出力できる
- アカウント運用（入職/異動/退職）手順が文書化済み
- 主要エラーでユーザーが次の行動を判断できる

## 7. 実装タスク（そのままチケット化可）

- T1: 強制パスワード変更フロー追加
- T2: ログイン失敗回数ロック実装
- T3: ロール追加とAPI権限制御
- T4: 監査ログのDB永続化
- T5: エラーメッセージ統一と再試行UI
- T6: 運用手順書（入職/異動/退職・棚卸し）確定

## 8. スコープ外（次フェーズ）

- SSO連携
- MFA
- 複数病院の高度統合運用
- 詳細分析ダッシュボード
